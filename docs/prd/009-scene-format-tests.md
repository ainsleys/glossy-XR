# 009 · Every scene format the viewer accepts is loaded by a test

## Problem

`client/src/loaders.js` loads glTF/GLB (with Draco, KTX2 and meshopt), PLY (mesh, point cloud, or Gaussian splat by header), PCD, OBJ with MTL, `.splat`/`.ksplat`/`.spz`/`.sog` through Spark, flat images, 360 panoramas and video. The suite exercises only the default room and, when a 60 MB interior is present outside the repo, one OBJ (`test/scene.spec.js`). The README records a manual check of each format on 12 Oct. A regression in any loader, in the Gaussian-PLY sniff, in the splat anchor cone test, or in auto-fit for a given format would pass the suite.

## Goal

Each format has an automated load test that runs on every machine, from small fixtures the test writes itself, plus an optional pass over real files when `../test-assets` is present.

## Requirements

R1. **Synthetic fixtures, generated by the test** (no large binaries in the repo), in `test/fixtures/scenes.mjs` as pure functions returning Buffers. Place every fixture **off the origin and off the floor** (e.g. centred at y = +2) and make one of them about 50 units across, so auto-fit's translation and scale rules are both exercised. Formats:
- a cube as ASCII PLY with faces (mesh), and the same vertices as PLY without faces (point cloud);
- a 3DGS PLY: **binary_little_endian**, header types spelled `float` (the sniff in `loaders.js` matches `property float f_dc_0` and `scale_0`), with all 14 properties Spark requires: `x y z`, `f_dc_0..2`, `opacity` (a logit of about 4, since centres with opacity < 0.1 are dropped), `scale_0..2`, `rot_0..3`; ~200 Gaussians on a sphere of known centre and radius;
- a `.splat` file of the same Gaussians in Spark's 32-byte layout: position f32×3, scale f32×3, colour u8×4 with alpha 255, rotation u8×4 as `w, x, y, z` encoded `q*128+128`;
- an ASCII PCD of ~500 coloured points, one of them at a known position to aim at;
- a minimal glTF (`.gltf` JSON with an embedded base64 buffer, one triangle-list cube);
- an OBJ cube with a sidecar MTL **sharing the OBJ's base name** and a known `Kd` colour;
- a 2:1 PNG panorama and a non-2:1 PNG photo written as raw PNG bytes in Node (`zlib.deflateSync`, `zlib.crc32`);
- a one-second WebM video recorded inside the page from `canvas.captureStream()` with `MediaRecorder` (no ffmpeg), then uploaded.

R2. **Per-format load test**, `test/formats.spec.js` under the `chromium` project, one test per format so a failure names it. For each fixture, upload it (`uploadAsset`; the panorama with `{mode: 'sphere'}`), then assert through `window.__glossy.loaded.get(id)`: the asset's `type` as the server classified it; `model.kind` (`mesh`/`points`/`splat`; images and video report `mesh` with `count` 4); `model.count > 0`; a bounding box with positive extent; the saved transform (`entry.asset.transform` or a GET on the project) non-empty; the **world** box (`model.box` through `group.matrixWorld`) with min y ≈ 0 for meshes, points, splats and flat images; for the panorama, scale 1 and the camera less than its radius from the origin; the default room hidden for scene types and the sphere panorama, and **still visible** for the flat photo and the video (that is the `isScene` rule). Anchoring: aim at a known point of the fixture (the points raycast threshold is 0.03, so aim at a fixture point, not the cloud's middle), record a short clip, and assert `anchor.objectId` (`'pointcloud'` for clouds, `'splat'` for splats, the mesh name for meshes); for the splat, assert the anchor's distance from the world sphere centre equals the radius times the scale within 5%. For the OBJ, assert the loaded material's `Kd` colour, so a missing MTL fails. Call `test.setTimeout(180_000)` on the splat and real-asset tests (`uploadAsset` waits up to 120 s).

R2a. **Spike first.** Run the `.splat` and 3DGS-PLY tests alone before writing the rest; Spark decodes in a worker and should load under SwiftShader, but this is unverified. If it cannot, mark those two tests skipped with the reason and report; do not change `loaders.js`.

R3. **Optional real-asset pass**: when `../test-assets` exists, the load assertions (not the anchoring ones) over `SheenChair.glb`, `cosmic-buddha-100k-2048_std_draco.glb` (Draco), `stanford_bunny_bun_zipper_mesh.ply` and `colored_cloud.pcd`; each skipped individually with a reason if missing. Not `hornedlizard.spz` (recorded in `test-assets/TEST-RESULTS.md` as decoding to noise in Spark 2.3.1) and not the 8192×4096 panoramas (SwiftShader's texture limit; skip with a reason). Licences per `LICENSES.md` are fine. Frame time logged, not asserted.

R4. **Error path**: an upload of a `.txt` is refused by the file filter (400, "file is required…"); a `.mtl` sent as the main file reaches the "unsupported asset type" branch (400); a file with a `.ply` extension containing non-PLY bytes (never a truncated 3DGS PLY: Spark's timeout is 180 s) is accepted by the server, and the client surfaces a truthy `loaded.get(id).error` (raw POST, then `waitForFunction`; `uploadAsset` asserts no error so it cannot be used here) without taking the page down.

R5. **README**: the test-coverage paragraph names the formats covered and the optional real-asset pass.

## Non-goals

- No change to `client/` or `server/` beyond what a bug found by a new test would need, and then only after reporting it; a loader bug is its own change.
- No performance assertions.
- No headset run (WebXR with splats on hardware is a separate session).

## Design

Fixture writers are pure Node functions returning Buffers; the spec writes them to a temp dir per test. Use `uploadAsset` from `test/helpers.js`. Keep per-format tests separate so a failure names the format. Total added fixture bytes written at runtime, not committed.

## Tests

T1. `npx playwright test test/formats.spec.js`: all formats pass on this machine (real-asset pass included). Mutations, each restored: (a) `isGaussianPly` returns false → the 3DGS-PLY test fails on `kind`; (b) `case 'splat': throw` in `loadModel` → the splat test fails; (c) `autoFit` returns without changing the transform → the world-box and scale assertions fail (the fixtures start off the floor and one is 50 units across); (d) `hitTest` returns null → the splat anchor assertion fails; (e) the MTL check returns false → the `Kd` assertion fails; (f) the `isScene` rule inverted → the default-room visibility assertions fail.

T2. Stability: `--repeat-each=3` on the spec.

T3. Full `npm test` at the final commit: all passed (the interior scene test runs here since the asset exists).

## Definition of done

- R1–R5; T1 with mutations, T2, T3 in the pull request.
- Commit messages and the pull request describe the change only.

## Decisions (3 Nov)

1. The 3DGS PLY must be binary little-endian with all fourteen properties and `float` types, or Spark rejects it and the sniff misses it; the `.splat` layout and quaternion encoding are specified to match Spark.
2. Assertions are per format: images and video are meshes with count 4; the panorama is centred at scale 1; flat photos and video leave the default room visible by design (`isScene`); `objectId` is set for every kind (`pointcloud`, `splat`, mesh name).
3. Fixtures start off the floor and one is large, so the auto-fit mutation can fail.
4. `hornedlizard.spz` is excluded (known to decode to noise) and the 8K panoramas are skipped under SwiftShader.
5. The corrupt-file case uses non-PLY bytes, never a truncated 3DGS file (180 s Spark timeout).
6. Spark under SwiftShader is unverified: spike first, skip with a reason if it cannot load, report rather than change `loaders.js`.
7. Two observations to report, not fix: a 2:1 image uploaded without `{mode:'sphere'}` leaves the default room visible; Spark's 180 s timeout exceeds any test timeout.
